# Mock Knowledge Base

## Purpose

The mock corpus demonstrates how a realistic internal knowledge system can organize, retrieve, cite, and govern company information without treating fictional text as official policy.

## Coverage

The prototype includes 30 fictional company-style documents and 109 chunks:

- COM Site: navigation and internal resource directory
- SOP Library: project setup, GIS data management, QA/QC, deliverable packaging, and client communication
- Sales Playbook: discovery, RFP/proposal workflow, and delivery handoff
- PM/PL Documents: kickoff, milestone review, client updates, risk escalation, and delivery readiness
- Field Team Resources: preparation, mobile/equipment readiness, notes, photos, and office handoff
- Tech Team Resources: automation intake, script review, data processing, QA automation, and knowledge ingestion
- RFP / Proposal Knowledge: intake, compliance, and evidence guidance
- Training / Onboarding: role-based onboarding and readiness records
- Project Templates: kickoff, decision, and client-status templates
- Delivery Standards: acceptance and client-facing presentation standards

## Metadata contract

Each mock document carries source group, document type, audience, category, owner, department, review status, confidentiality, tags, summary, sections, chunks, related documents, example questions, replacement note, required inputs, expected outputs, and common mistakes.

## Replacement rule

Mock content must never be promoted into production as policy. Each record is replaced by an authoritative source with an owner, source-system ID, effective date, review date, permission groups, version history, and approval evidence.
