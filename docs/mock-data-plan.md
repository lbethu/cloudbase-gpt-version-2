# Mock Data Plan

## Why mock data comes first

Internal operating documents may contain client, contract, personnel, security, or proprietary information. A mock-first prototype allows the team to review the workflow without copying sensitive material into an unapproved environment.

## Included mock sources

The expanded corpus contains 22 documents and 85 chunks across COM Site, SOP Library, Sales Playbook, PM/PL Documents, Field Team Resources, Tech Team Resources, and Training Materials. It covers project delivery, GIS data management, QA/QC, sales discovery, RFP response, field collection, client communication, risk, automation, script review, and knowledge ingestion.

The language is plausible for a geospatial consultancy but is entirely fictional.

## What reviewers should evaluate

- Whether the categories reflect how employees seek knowledge
- Whether document metadata is sufficient
- Whether answers are clear and appropriately grounded
- Whether confidence and suggested actions are useful
- Whether source inspection provides enough context
- Whether upload review states match the desired governance process

Reviewers should not evaluate the mock statements as official policy.

## Replacement rule

Mock records should be replaced only with approved, owner-assigned, classified source records. Real ingestion should preserve the same interface contract while adding source-system identifiers, permissions, effective dates, review dates, and document-version metadata.
